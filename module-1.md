# The "DevOps Mindset" Shift

As a new grad, you're used to:

Writing code → compiling → running → "it works on my machine!"

## DevOps is different:

Writing code → packaging → deploying → running on 100s of servers → "it works for everyone, all the time, with zero downtime"

Think of yourself as the **bridge** between:

**Developers** (who write features)

**Operations** (who keep servers running)

**Business** (who want features shipped fast and safely)

Your job is to automate everything so that deploying code becomes boring, routine, and error-free.

# Our Learning Philosophy

| Rule |Explanation|
|------|-----------|
|Type, don't copy-paste	| Muscle memory matters. If you type every command, you'll remember it.|
|Break things intentionally	| Change a port, delete a file, stop a container. Learn how to fix it.|
|Ask "why" 3 times	| Don't just run `docker run nginx`. Ask: Why containers? Why Nginx? Why port mapping?|
|Document everything	| Write notes in your own words. If you can explain it to a 5-year-old, you understand it.|

## DevOps 

DevOps is a process of improving the application/script/binary delivery 
by ensuring:
```
|	- Culture that improves delivery
|
|--> Automation
|--> Quality
|--> Continuous Monitoring
|--> Continuous Testing

```
## ex
```
example.com talking 10 days ---> (v1 to v2)
                          |
                          |----> Hours | 1 or 2 days
```

- Faster Delivery
- Increased Reliability
- Better Collaboration
- Efficiency at Scale
